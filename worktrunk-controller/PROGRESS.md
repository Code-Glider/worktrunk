# Controller implementation and qualification

Goal: implement the eight stages in [AUTOMATION_PLAN.md](../AUTOMATION_PLAN.md) and publish verified code/tests to the fork. User direction: keep delivery on GitHub for now. Local clones and disposable fixtures are for development/verification; real deployment, host installation and real cleanup scheduling are deferred. The first preservation fix is on PR #1; the remaining roadmap is not complete. Deployment-specific gates remain explicit and cannot be claimed passed by CI fixtures.

## Execution plan

1. Establish configuration, durable shared state and incarnation evidence. Reuse the version-1 Project Mission Control registry (`projects[].id/root`). Use Node 24.15+ ES modules and built-in SQLite on one native local filesystem. Explicit enrollment writes a marker in Git administrative storage and binds it to native directory/file identity; observation never enrolls. Check: real two-process acknowledged writes, interrupted transaction, disk-full/corruption, schema rejection and same-path recreation tests pass.
2. Qualify isolated Worktrunk observation and build the analyzer. Reuse schema-2 list and Git plumbing, scrub Git discovery variables, disable callbacks, constrain scratch and bind integration to the named ref vector. Check: mixed-state decisions explain every item; ignored/hidden files, nested repositories, stale entries and probe failures retain data; refs/index/content and unrelated scratch sentinels survive.
3. Integrate normalized host/session and authoritative task events. Read the actual launcher/task source before selecting adapters. Keep identity namespaces distinct, deduplicate replay and expose partial coverage. Check: host behavior survives recording failure; concurrent producers, restarts, gaps, out-of-order events, moves and independent sessions have exact projections.
4. Implement backlog and throughput reports. Check: fixed real event timelines assert weekly task acceptance, first-attempt outcomes including cancellations, retries, median/p95 durations, reopen/revoke, attribution, waiting/overlap and unavailable evidence; replay changes no totals.
5. Implement cooperative producer admission and target-specific claims. Check: two-process launch/cleanup races, interrupted startup, PID reuse, suspended producers and overlapping roots cannot admit conflicting cleanup; unresolved ownership remains protected.
6. Implement quarantine and restore using native Git worktree moves or same-filesystem artifact moves. Check: manifests/intents survive injected crashes, round trips preserve contents and registration, and occupied destinations, links, cross-device roots and protected content veto mutation.
7. Implement selected apply/purge with isolated native Worktrunk removal and shared-policy revalidation. Check: only selected targets change; refs/policy/content/owner/clock changes and hooks veto; unrelated trash/processes survive; partial failures are durable and fail the batch.
8. Document/package scheduling and run disposable end-to-end qualification, then review and publish. Check: repeated scans, restarted controller, host/task adapter fixtures, quarantine/restore/expiry/purge and recovery pass; relevant existing Worktrunk gates and controller tests pass. Real scheduled deployment and actual host/task-event qualification are deferred under the GitHub-only direction; they require configured owner/root/retention/outcome authority and a qualified deployment.

Each stage will record exact commands/results here before it is marked complete. `node --test worktrunk-controller/tests/*.test.mjs` is the controller gate; Rust changes use the declared 1.98 toolchain and repository checks. Do not silently replace an acceptance check with a smaller unit test.
